# Approximate voice cue Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Highlight an estimated current word, pause text during silence and allow tapping a word to correct position.

**Architecture:** Keep the existing fixed mode as default. A deterministic weighted-word cursor runs from the selected duration; an audio-level gate enables its clock only while sound exceeds an adjustable threshold. Meter the existing capture session using AVCaptureAudioDataOutput, without recognition, server requests or storing practice audio.

**Tech Stack:** Swift 6, SwiftUI/UIKit TextKit, AVFoundation, existing PrompterCore package.

**Spec:** Approved conversation on 2026-10-19: approximate pace + silence pause + correction by tapping, not word recognition. Implementation choices below are defaults chosen by the implementer.

## Global Constraints
- KISS; iOS 17+, Hebrew RTL, no added dependencies or backend.
- Existing scripts decode with follow disabled; recording timer continues during all text pauses and after end of text.
- Optional follow requires microphone permission even in practice; denial offers ordinary practice.
- Highlight uses cached word ranges and layout; never remeasure the whole script on every frame.
- Sound gate is not semantic voice detection; explain sensitivity to background noise.

## Review Focus
- Stale or missing audio must stop the cue, not keep it moving.
- Manual pause must take precedence over loud sound.
- Old saved settings must decode without losing scripts.
- RTL/mixed text taps must select the actual character and scroll its line to the cue.
- Audio resources must stop on finish, cancellation, failure and departure; movie audio must remain intact.
